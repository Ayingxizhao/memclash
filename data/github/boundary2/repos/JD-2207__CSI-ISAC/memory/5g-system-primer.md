`literature/explainers/5g-system-primer.md` (~1840 lines, 21 mermaid diagrams) is a standalone
top-to-bottom 5G explainer the user asked for because the system-level material is out of thesis
scope. Written against **Release 19**, with `[R16]`/`[R17]`/`[R18]`/`[R19]` tags on features.
Scope the user cares about: **IV.F, IV.G, IV.J, Part V, Part VI**. They explicitly said to skip
power-on, security, authentication and handover.

**The approved structure is a "zoom ladder"** (§IV.F is the reference implementation of it):
start from the single most comprehensible artefact, and each level *zooms into one box of the
previous level's figure*, ending with a "**What this raises**" list that forward-points to the level
answering each question. Figures renumbered F-1…F-9, local to the section.
§IV.F runs F.0 (how to read) → F.1 (six sentences, zero jargon) → F.2 (look-up table) → Levels 1-10
→ **F.16, the capstone Figure F-9** = `figures/5g_frame_waterfall.svg`, generated by
`scratchpad/gen_frames_fig.py`. **Frames are DRAWN, not described** — the user's own correction after
a first attempt as a 14-column mermaid sequenceDiagram: a sequence diagram can only put information in
label text, so twenty PDUs became twenty paragraphs. The SVG is an encapsulation waterfall — network
stack building down the left, phone stack undoing up the right, a peer line across the middle at each
layer saying what dies there, GTP-U/F1-U/eCPRI flagged as one-hop wrappers with no peer, payload in one
constant colour so it is visibly the only survivor, plus a control-loop panel (CSI-RS / CSI report /
grant / ACK, none rising above MAC). Worked numbers are self-consistent: MCS 15 = 16-QAM at 616/1024,
TBS 167 976 bits = 20 997 B, 20 code blocks × 8400 + CRC24B, LDPC BG1 lifting 384, 279 552 coded bits,
69 888 QAM symbols, CP 288/352 samples, fronthaul 3.3 vs 106 Gbit/s.

**One integrated figure, not sections.** Header = order-of-events strip + slot timeline (K0/K1/N1) +
what RRC configured. Body = the per-layer waterfall. **Each control frame is drawn inside the row of
the layer that CREATES it**, in a shaded band: RLC STATUS PDU at RLC, the grant (DCI 1_1 field by field
+ Polar/CCE chain + blind decoding) and the HARQ-ACK at MAC, CSI-RS and the two-part UCI report at PHY.
Only three bands, none above MAC — that placement turns "no control frame is born above MAC" from a
claim into something visible. Uplink mirror as a footer.

Two user corrections drove this, both worth remembering:
- **"it seems way more simple"** — the first redraw silently dropped ~45 of 49 spec facts by collapsing
  the control plane into four one-line arrows.
- **"can't you put them altogether?"** and **"what happens before, user or control plane?"** — a
  two-section layout implies the planes are sequential. They interleave and **cross at RLC** (RLC cannot
  cut the packet until the grant says how much room there is; same boundary as the CU/DU split). The
  figure now marks that gate explicitly and opens with the 6-step order strip.

**Two lessons that generalize:**
1. A sequence diagram is right for *flow* (order, path, termination); a drawn figure is right for
   *structure* (what a frame is made of). Don't force the second into the first.
2. **When replacing one artifact with another, diff the information content, don't eyeball it.**
   Extract text from both (mermaid source vs SVG `<text>`+`<desc>`), probe a list of spec terms and
   numbers, and report what was lost. Cheap, and it catches silent regressions a screenshot never will.
Hand-drawn SVGs follow `figures/*.svg` house style — `<title>`/`<desc>`, CSS custom properties with
`prefers-color-scheme` + `[data-theme]` dark variants, system-ui + ui-monospace. Markdown strips inline
`<svg>`, so figures must be files referenced with `![]()`; from `literature/explainers/` that is
`../../figures/`. Generator must compute segment widths from measured text (len × size × 0.55 sans /
0.62 mono) or labels overflow their boxes.

**Mermaid gotchas learned the hard way — always render-check, never eyeball:**
- Semicolons are statement separators: they break any diagram if used inside label text.
- `<-. "label" .-` is invalid syntax; the bidirectional `<-. "label" .->` works.
- **Multi-line message labels (`A->>B: x<br/>y<br/>z`) get the arrow drawn *through* the last line.**
  Fix = append a trailing `<br/>`. `&nbsp;` renders literally, so don't use it.
- Notes over a *single* participant widen that column; spanning two (`Note over A,B`) halves the cost.
  Keeping note lines ≤ ~45 chars took Figure F-9 from 7302×5015 (unreadable) to 4765×7606 (scrolls).
- `box transparent <title>` groups participants; `rect rgba(128,128,128,0.10)` gives theme-safe phase bands.
- Stack figures: `flowchart LR` with `direction TB` inside subgraphs, so peers align horizontally.

**Render-check workflow** (scratchpad `genmer.py` + headless Chrome): extract every fenced mermaid
block, call `mermaid.render()` (not just `parse`) under mermaid@11, then *screenshot and read it* —
syntax-valid diagrams still lay out wrongly. Chrome needs `dangerouslyDisableSandbox: true`, an
absolute `--user-data-dir`, an absolute `--screenshot` path (relative paths silently reuse a stale
file), and a Windows-style `file:///C:/…` URL. PIL is not in base python — use the `venv` env for
cropping.
