DECISIONS.md entries must read like a real decision/discussion between the user and me — NOT a description of what the thing is. Each entry, concise, in the user's first-person voice: who proposed it ("my call" / "Claude proposed"), what the user pushed back on, what they agreed / didn't agree on, the trade-off, and the reason.

**Why:** the assessment grades DECISIONS.md as a record of how we collaborated and where the AI was overridden (§2.1, §2.3) — the strongest signal in the submission. Dry "Decision / Why / Cost" bullets read as documentation and miss that.

**How to apply:** write each entry as a short narrative of the back-and-forth (like the §2.1 sample: "Claude proposed X. I pushed back — reason. Landed on Y. Cost: Z."). Keep it concise. Relates to [[track-project-decisions]] and [[communication-direct-concise]].
